# OpenAI Build Week Submission Checklist

## Required

- [ ] Register on Devpost.
- [ ] Choose the Education track.
- [ ] Confirm the representative is eligible to submit.
- [ ] Provide a working project.
- [ ] Provide a public YouTube demo video under 3 minutes.
- [ ] Explain how Codex and GPT were used.
- [ ] Provide a repository link for judges.
- [ ] Include setup and run instructions.
- [ ] Include testing instructions.
- [ ] Include the primary Codex feedback/session ID if required by the form.
- [ ] Submit before the deadline.

## Repository Readiness

- [x] README explains the educational model.
- [x] README includes setup and build commands.
- [x] Devpost submission draft is prepared.
- [x] Video script is prepared.
- [x] Learning method is documented.
- [ ] Public repo is reviewed for secrets.
- [ ] Public repo is reviewed for private personal data.
- [ ] Public repo is reviewed for unnecessary private logs.
- [ ] Latest build is verified.
- [ ] Demo URL is tested from a phone or public browser.

## Privacy Review

- [ ] No API tokens.
- [ ] No bot tokens.
- [ ] No private chat exports.
- [ ] No phone numbers.
- [ ] No private student data.
- [ ] No screenshots showing private conversations.
- [ ] No copyrighted music in video.
- [ ] No unlicensed third-party art or brand assets.

## Demo Video Checklist

- [ ] English narration or English subtitles.
- [ ] Project title appears in first 5 seconds.
- [ ] Education problem is clear.
- [ ] Method is explained.
- [ ] Prototype is shown running.
- [ ] Codex/GPT usage is explained.
- [ ] Video is less than 3 minutes.
- [ ] YouTube video is public or unlisted/publicly visible as required.

## Submission Copy Checklist

- [ ] Title: VibeCoding Business Studio.
- [ ] Track: Education.
- [ ] Tagline is under one sentence.
- [ ] Description explains that this is a repeatable method.
- [ ] It does not depend on a parent/child story.
- [ ] It mentions schools, clubs, and private projects.
- [ ] It explains vibe coding plus business plus teamwork.
- [ ] It distinguishes previous work from Build Week work.
- [ ] It explains what judges can test.

## Risk Notes

- This project started before Build Week, so the submission should clearly
  describe what was meaningfully extended during the submission period.
- The public pitch should avoid personal family framing and focus on the
  repeatable education method.
- The prototype should be presented as a demo vehicle, not as the whole product.
