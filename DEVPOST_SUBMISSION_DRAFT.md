# Devpost Submission Draft

## Project Title

VibeCoding Business Studio

## Tagline

An AI-assisted project studio where students learn vibe coding, business, product
thinking, and teamwork by shipping a real prototype.

## Track

Education

## Elevator Pitch

VibeCoding Business Studio is a repeatable learning method for schools, clubs,
and private projects. Students use Codex as a build partner while they act like a
real product team: they define the idea, scope it down, assign roles, build a
prototype, test it, and connect technical choices to business reality.

The demo project is TempleFall, a mobile-first battle royale prototype. The game
is the learning vehicle; the real product is the educational operating system
around it.

## Inspiration

AI makes it possible for young learners and nontraditional builders to make real
software faster than ever. But speed alone does not teach judgment. Students also
need to learn how to decide what to build, how to scope it, how to work with
others, how to think about customers, and how to connect product decisions to
business consequences.

This project started as a private game-building project and evolved into a
method: use a real prototype as the classroom, and use Codex as the technical
partner that lets the learner stay in the role of product owner.

## What It Does

VibeCoding Business Studio helps learners run a project like a small studio:

- define a product vision;
- turn vague ideas into a smaller playable prototype;
- use Codex to implement and debug;
- track progress and decisions;
- learn business concepts in context;
- invite teammates into clear roles;
- document what each person is responsible for;
- keep adult/teacher supervision for permissions and high-risk decisions.

The included demo is TempleFall, a mobile-first Phaser prototype with:

- a jungle battle royale concept;
- touch/click movement;
- bots;
- loot;
- health, shield, ammo, and relics;
- a shrinking vegetation zone;
- temple objectives;
- a secret-room reward;
- a vending machine mechanic.

## How We Built It

We used Codex as the main build partner:

- to structure raw student ideas into game design documents;
- to implement the prototype in TypeScript and Phaser;
- to debug mobile layout and screen-rendering issues;
- to create a team coordination process;
- to frame technical decisions as business lessons;
- to prepare the project for Devpost submission.

The project uses TypeScript, Phaser, Vite, Capacitor Android, Git, and GitHub.

## How We Used Codex and GPT

Codex was not only used to generate code. It was used as an educational
coordinator:

- builder: implementing scenes, controls, gameplay systems, and docs;
- debugger: reading errors, testing builds, and fixing mobile display problems;
- product coach: reducing ambitious ideas into an achievable vertical slice;
- business coach: connecting features to customers, costs, pricing, marketing,
  and teamwork;
- project manager: maintaining progress notes and coordination rules.

The learner remained the CEO/product owner. Codex accelerated implementation but
did not replace ownership of the idea.

## What Makes It Different

Many AI education projects focus on tutoring or quizzes. This one focuses on
project ownership.

Students learn by building something they care about, but the method forces real
constraints:

- scope matters;
- teams need roles;
- percentages and responsibilities should be clear;
- features have cost;
- users need a reason to care;
- shipping a small working prototype beats dreaming about a huge unfinished app.

## Challenges

- The original idea changed, so the system had to accept a pivot instead of
  forcing the old plan.
- The game vision was much larger than the current stack, so we had to separate
  long-term ambition from a practical vertical slice.
- Mobile rendering had to be adjusted so the prototype is visible and usable on
  phone-sized screens.
- The project needed to be reframed from a private learning project into a
  repeatable method for schools and private teams.

## Accomplishments

- Built a playable mobile-first prototype.
- Converted a large game idea into staged product planning.
- Created a model for student-led team roles.
- Added business coaching directly into the build workflow.
- Prepared documentation that explains both the software and the educational
  method.

## What We Learned

AI can help students build faster, but the bigger educational value is judgment:
learning what to build first, how to test it, how to work with others, and how
product decisions connect to business outcomes.

Vibe coding is powerful when it is paired with ownership, documentation, and
realistic constraints.
